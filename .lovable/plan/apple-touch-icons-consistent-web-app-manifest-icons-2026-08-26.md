# Apple touch icons + consistent web app manifest icons

## What's happening now

- The home-screen icon points at `/pwa-192x192.png`, which is actually a 1024x1024 file with a cream background — iOS downscales it itself and there is no true 180x180 Apple touch icon.
- `pwa-512x512.png` has the same problem (1024x1024, cream background, no maskable safe area), so Android/Chrome install icons don't match the new dark gold Storm favicon.
- The manifest is generated by the PWA plugin at build time; there is no `<link rel="manifest">` in `index.html`, so nothing references it in dev or in tools that read the raw HTML.

## What will change

1. Generate a matching square icon set from the same Storm gold mark used for the new favicon, all on the dark `#0d0d0f` brand background:
   - `public/apple-touch-icon.png` — 180x180 (Apple requires an opaque, non-transparent square; no rounded corners, iOS masks it)
   - `public/apple-touch-icon-152x152.png` and `-167x167.png` for older/iPad devices
   - Regenerate `public/pwa-192x192.png` and `public/pwa-512x512.png` at their real sizes with the dark brand background
   - `public/pwa-maskable-512x512.png` — same mark inset to ~80% so Android's circle/squircle crop never clips it
   - `public/favicon-32x32.png` and `public/favicon-16x16.png` for crisp browser tabs
2. Update `index.html`:
   - Point `apple-touch-icon` at the real 180x180 file, add the 152/167 sized variants
   - Add the 32/16 icon links alongside the existing `/favicon.png`
   - Add an explicit `<link rel="manifest" href="/manifest.webmanifest">`
3. Update `vite.config.ts` PWA manifest:
   - Icon list becomes 192 (any), 512 (any), and the dedicated maskable 512
   - Add the new icon files to `includeAssets` so they ship and are precached
   - Keep `manifest.webmanifest` as the emitted filename so the hard-coded link matches

Existing PWA behavior (`selfDestroying`, registration guards, push worker `sw-push.js`) is left untouched — this is icon/manifest metadata only.

## Notes

Home-screen icons are cached aggressively by iOS and Android. After publishing, an already-saved shortcut may keep the old icon until it is removed and re-added; fresh installs pick up the new one immediately.
