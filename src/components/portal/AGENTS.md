- Client PT portal pages (/member and /portal personal-training) read only through `pt_my_portal()`, which returns client-safe fields; never select raw PT rows there. Why: client-owned PT rows carry staff-only notes columns.
- Client PT requests are read only through `pt_my_requests()` (no client SELECT policy on training_requests); the portal follows the approved Overview → Request Session → Requests + Upcoming layout, and submission stays disabled (`REQUESTS_ACTIVE` plus the server staff-only lock) until the owner activates it. Why: request rows hold staff notes and the flow is owner-approved.
